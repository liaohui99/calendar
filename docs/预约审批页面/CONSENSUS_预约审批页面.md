# 预约审批页面 - 需求共识文档

## 确认后的需求

基于原始需求和项目现状分析，我们对预约审批页面的功能达成以下共识：

1. **页面功能**：
   - 查询所有预约信息，以表格形式展示
   - 提供修改预约状态的功能，支持通过和拒绝操作
   - 预约状态包括：待确认(PENDING)、已确认(CONFIRMED)、已取消(CANCELLED)
   - 通过操作将状态从PENDING更新为CONFIRMED
   - 拒绝操作将状态从PENDING更新为CANCELLED

2. **UI设计**：
   - 遵循现有项目风格，使用Semi Design组件库
   - 实现表格分页功能
   - 提供基本的筛选功能（按状态筛选）
   - 操作前提供确认提示
   - 操作成功后显示成功提示

3. **API支持**：
   - 使用现有的`getReservations`接口获取预约列表
   - 新增更新预约状态的API接口调用封装
   - 假设后端已规划或需要同步开发相应API

## 验收标准

1. **功能验收**：
   - 审批页面能够正常加载并显示所有预约信息
   - 表格支持分页浏览
   - 能够成功通过和拒绝预约，状态更新正确
   - 操作前有确认提示，操作后有成功反馈
   - 能够按状态筛选预约列表

2. **技术验收**：
   - 代码符合TypeScript规范，无编译错误
   - 组件结构合理，遵循React最佳实践
   - 所有组件都有对应的测试用例
   - 测试用例全部通过
   - API调用错误处理完善

3. **UI验收**：
   - 页面布局清晰，符合Semi Design设计规范
   - 表格列信息完整，包含预约所有关键信息
   - 操作按钮明确可辨
   - 响应式设计，适配不同屏幕尺寸

## 技术方案

### 前端实现方案

1. **页面组件**：
   - 创建`ApprovalPage.tsx`作为主页面组件
   - 使用`Table`组件展示预约列表
   - 使用`Pagination`组件实现分页
   - 使用`Select`组件实现状态筛选
   - 使用`Button`和`Popconfirm`组件实现状态更新操作

2. **数据获取与更新**：
   - 使用现有`reservationApi.getReservations`获取预约列表
   - 扩展`reservationApi`，添加`updateReservationStatus`方法
   - 实现数据加载状态和错误处理

3. **状态管理**：
   - 使用React hooks（useState, useEffect）管理组件状态
   - 管理加载状态、预约列表数据、筛选条件等

4. **文件结构**：
   ```
   src/
   ├── pages/
   │   └── ApprovalPage.tsx  // 审批页面组件
   ├── components/
   │   └── ApprovalTable.tsx  // 审批表格组件（可选）
   ├── services/
   │   └── api.ts  // 扩展API服务
   └── tests/
       └── ApprovalPage.test.tsx  // 测试用例
   ```

### API调用设计

1. **获取预约列表**：
   - 调用路径：`/api/reservations`
   - 支持参数：`deviceId`(可选), `date`(可选), `status`(新增，用于筛选)
   - 返回数据：预约列表

2. **更新预约状态**：
   - 调用路径：`/api/reservations/:id/status`
   - 请求方法：PUT
   - 请求体：`{ status: ReservationStatus, reason?: string }`
   - 返回数据：更新后的预约信息
